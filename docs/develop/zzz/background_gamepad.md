# 纯手柄后台运行

## 输入边界

后台模式使用虚拟手柄和 PrintWindow。后台任务不得移动系统光标、发送全局键盘输入、使用剪贴板粘贴或切换前台窗口。用户的签到地点、任务列表和运行记录不因适配而改写。

通用控制器负责输入边界；绝区零控制器负责界面手柄导航。已有 `gamepad_key` 继续用于打开菜单、地图等快捷动作。坐标目标只有在已识别的页面和选中框内才能确认；导航后重新截图检查焦点，不把发出按键等同于业务成功。

未适配的操作抛出 `BackgroundInputError`，逐层执行操作结束清理后终止本次运行，不重试为前台输入，也不把失败任务记录为成功。应用组恢复当前应用上下文，最外层运行器记录失败原因。

## 页面导航

菜单底部为横向焦点列表。地图包含主区域网格和底部传送点列表，确认主区域后进入传送点列表，返回键回到主区域网格。传送点确认弹窗另行识别，确认后由原传送流程检查落地画面。

选中框在黄色和黄绿色之间变化。识别需要同时满足颜色、矩形外形和边框连续性，并限定在页面声明的导航区域。每次只发一个方向键；下一步由新的截图决定，不根据按键次数假定焦点已经移动。

枯萎入口在已有未结束探索时会隐藏其他区域名称；此时以「探索收集」「作战机略」和仍可见的已知区域识别。继续弹窗必须完整匹配当前配置关卡，并确认按钮获得焦点，才按 A。正文缺失时不得落入通用确认；已识别正文但按钮缺失则明确失败。接力完成不能计作从入口开始的一轮无中断验收。

枯萎之都保留原来的事件目标和鸣徽优先级。电视行走将选中的鼠标点击路标转换为逐格最短路径，中途只经过已通行格；原来按点击次数计算的零成本路径与重复点击补救不适用于手柄。发出方向键后保留待确认格，必须由新截图中的当前位置确认到达，才能更新访问记录。事件遮住地图期间先处理事件，恢复地图后再确认。连续二十次有效位置观察仍未到达则失败；暂停期间没有观察，不计入次数。

鸣徽选择包含 SS 等级，具体名称优先级按分类后的名称匹配。新版本「助战」名称映射到已有「邦布」分类，用户配置不改写。商店只考虑黄色可支付价格的商品，按原购买优先级选择；通过商品右侧 A 提示确认焦点，购买后等待战利品页。事件选项按同一行合并 OCR 片段，以免选中前后分词变化导致丢失目标。

鸣徽导航忽略 OCR 的括号与空格差异，分类和名称仍要求唯一一致。防卫军「公平交易」后的「丢弃冗余」是批量预览，底部丢弃按游戏规则处理整批，不提供单卡优先级选择。后台仅在完整标题、丢弃类型和唯一按钮焦点一致时确认一次，观察到战利品标题及确认按钮后完成；其他丢弃／抵押页面明确失败。事件选项沿用原配置，不因适配改选其他交易。

速刷的普通事件优先选择当前页面可见的离开项；同一事件后续页若必须选择援助，则按既有顺序保留配置未标注扣血的选项，离开项同样排除已标注扣血者。反向 OCR 匹配保留完整配置名称，近名同分时拒绝确认，避免被排除的大袋子误匹配成小袋子。未填写效果描述的事件无法仅凭配置保证不扣血。不能因为事件配置中某一页存在「离开」，就删除后续页全部可选项，也不能随机点击正文继续。

战斗后的残留 X 输入可能将鸣徽翻到背面；完整名称识别失败时，只有已知背面名称位于唯一焦点卡内，才按 X 翻回并重新识别，不能跳过该卡或改变配置优先级。此问题导致过新进程连续通关验证失败，翻回逻辑已单独实机验证。

首领结算直接识别「挑战结果」后停止战斗输入；若残留 X 已打开暂离弹窗，必须同时匹配完整暂离提示与取消按钮，停止战斗输入后按 B 取消，重新确认结算页。确认后等待换层时同样处理晚到弹窗；仅在取消过弹窗后，才用新截图复核结果页并重新确认一次，普通慢转场不重复按 A。沿用该节点三十次／六十秒失败上限。只有新截图的下一层层数和有效地图才能更新楼层，单独看见确认按钮不代表可以继续。

普通枯萎流程的商店必须确认鸣徽交易或特价折扣标题，并完整识别当前三个卡槽的名称和价格；缺失识别会重试，不能作为无商品或无优先级商品直接离开。血汗交易不参与购买。速刷沿用跳过购买的策略，自动进入商店时，在确认商店标题后直接返回，不要求识别商品。外层事件识别也能从商店标题恢复此流程。事件中的灰色禁用项不参与选择。持续未消失的消息提示、商店返回和战后切层有失败上限，超时不视为成功。

传送点以稳定新图中的格子排列确认换图：分别对齐旧头像格与旧传送格，排除缩放、只走入目标格和单纯漏检；两种对齐各自都需冲突多于一致，合计至少两个独立的新格发生类型冲突，才更新阶段。出生点在地图边缘时，一种对齐可能只重叠一个格，此时还要求新头像框与旧头像框、旧传送格框都不重叠；同一个新格不能重复凑数。证据不足时重试并明确失败。普通方向移动以目标格确认。轨道仅接受地图中唯一的有向出口，缺失、分叉、循环均停止；弹射的实际落点尚未实机验证。战后必须看见下一层层数和有效电视地图，才更新楼层并清除旧层待到达格，单独看到背包不能证明换层；战斗中接力导致旧层未知时，直接采用已观察到的新层数。

后台寻路只使用本帧电视地图，避免合并缓存保留已经消失或误识别的格子。「残破的障碍物」需要多次撞击；仅在头像仍在原格、障碍物仍可见时继续，次数不超过条目配置。破墙后可能出现空格或鸣徽催化剂等物资，确认新格后重新规划。每次重新观察画面，破墙和发送按键均不记作已到达。

施工废墟可能在移动后移除旧排并平移镜头。旧坐标无法确认时，将旧目标格及旧头像格分别与新头像对齐：目标视角至少两个类型匹配且没有冲突，匹配多于原位视角，原位视角至少两个冲突，再结合头像位置稳定确认移动。两种视角共用头像尺度，匹配为一对一，新头像格不参与类型比较；大电视不使用这一补充判据。该方法依赖相邻格类型识别，不能保证任意动态事件或误识别下都能通过。

施工废墟增援完成后，同列相邻的另一增援格可能变为硬币箱；这对转换在两种对齐视角中都不计作位置证据，其他独立地标仍须满足上述匹配与冲突门槛。四格尾段有连续硬币时，选择后方不同类型的地标作图案核对，不能拿两个相同硬币图案证明移动。

邦布插件使用 X 打开列表、左右选择、A 使用，名称不匹配不能使用；遍历回到已见名称时明确报告缺少插件。插件使用后需观察列表关闭。菜单退出使用 Start、Y 放弃，识别完整放弃提示及确认焦点后 A，结算页 B 关闭，最后观察到入口才算退出完成。

施工废墟的单行尾段缩短一格时，仅比较头像、目标及有名地标，忽略外围已通行空格。旧头像、目标和后续地标必须依次位于同一行；目标本身不参与地标冲突计数，多排地图仍用普通判据。目标视角对齐以外，还要求头像右移、地标左移，幅度超过旧格宽四分之一减去 4 像素检测误差，并观察地图稳定。保存移动前截图，比较格子内部有色图案的 HSV 直方图：未知目标与旧地标交集低于 0.35，已识别的不同类型允许近色，但目标及中间格与地标的交集不能达到 0.75；新旧地标交集至少 0.75。这些检查排除漏识的第二个同类地标，但仍依赖图案与类型识别，不能保证任意误识别下都能确认。已有三、四、五格及额外空格留档回归。末端商人或危机后重开地图的分支仅用于施工废墟：旧图只剩头像和末端格，新图必须在旧图左侧展开多排多列及多种类型，且头像稳定；确认后清除旧地图访问缓存，不增加楼层或奖励次数。

传送后的地图缩放期间，方向键可能被游戏忽略。规划移动前要求新截图中头像格的位置和尺寸连续稳定半秒；半秒是观察窗口，成功仍由移动后的头像位置保证，不能仅靠延迟认为输入有效。

跨多个已通行格前往鼠标规划的路标时，后台模式保留该路标直到到达。否则每走一个免费空格就重新选路，旧点击计费可能在上下两条路线之间反复切换。事件、暂停、传送、区域更换或路标不可识别会清除此临时路线；它不改变事件目标和用户优先级。

保留路标前等待头像稳定，并检查到达位置与旧目标中心及尺寸一致；镜头平移或缩放后清除屏幕坐标路标，避免将移入旧矩形的同类格误当作原路标。停止后若已在挑战结果页，重新进入战斗结算流程，仍需观察下一层后才更新层数。

盲盒奖励全部走空时，旧环形区域没有可比较的地标。仅对「不宜久留」出口增加特殊确认：旧图至少八格且只有头像、出口和已通行空格，头像与出口均在最右列；新头像明显移到左侧，新图从头像向右展开至少两排三列、五个有名格及三种类型，并通过稳定性观察。普通传送不使用此判据。

盲盒入口的小图可能与主图只重叠一个格。已发送盲盒移动后，新图必须出现原图没有的唯一「不宜久留」出口，且包含多排多列及至少两种其他事件。进入时保存实际观察到的主图；离开时可用原主图中至少两个地标的相对位置和类型确认返回，冲突或证据不足时继续等待。返回和换层后清除该临时地图。

盲盒入口和返回的补充判据均排除原位证据：如果按旧头像对齐后，仍有至少两个具名地标一致且没有冲突，则不能仅因出口出现或消失而确认换图。商店返回也必须重新看到背包及有效电视地图，按下 B 本身不计成功。

盲盒有时直接在主图结算：只有新画面没有「不宜久留」，且普通移动的地标判据确认已进入原盲盒格时，才接受就地结算，不保存独立区域来源，也不增加阶段或清空既有访问计数。普通传送点不能使用这一分支。换图和原图移动均按头像尺度对齐，避免目标检测框宽度差异制造互相矛盾的证据。

换图证据优先于就地结算推断。就地分支仍是视觉启发式：稳定半秒不能严格排除随后才开始的传送动画，当前缺少覆盖所有盲盒转场的时序证据，因此不能保证任意盲盒变体都能连续运行。

五格十字盲盒允许中间按钮漏识，但必须确认上下对齐的头像、唯一出口及中间一排三格。返回主图只剩头像和一个地标时，该地标必须与入口前原图吻合、在区域内未出现，且多排区域已缩为两格；仍会拒绝与区域内同名地标混淆的画面。这些条件已加入正负例回归，不能代替任意误识别下的保证。

运行结束时，停止、启动和暂停／恢复共用可重入锁；设备释放完成后才发布停止状态。释放失败存入运行结果，应用和独立操作都报告失败。此顺序防止清理尚未完成时恢复运行；现有自动战斗工作线程的完整退出仍需另行验证，不能据此宣称所有后台工作线程已归零。

源码复核确认一个既有调度限制：`OperationExecutor.stop()` 不等待已提交的 `execute` 子任务，普通优先级打断后旧 executor 引用也会被替换。因此释放按键后仍可能有旧动作写入虚拟手柄；只等待当前 executor 无法覆盖此前被打断的子任务。此次未改造任务调度生命周期，晚到暂离弹窗采用上述可观察且有限次的恢复，不宣称消除了全部残余输入竞态。

## 当前验证范围

战斗重试按手柄菜单的 X 重新开始，核对「是否重新开始战斗」及确认焦点后按 A，每步只发送一次。确认后等待攻击按钮重新出现才返回成功，加载重试预算不代替画面证据。重试沿用原有次数上限，不改队伍、任务进度或完成记录。

达到重试上限后，后台模式直接保存当前现场，不打开藏品地图；退出使用战斗菜单 Y 和明确的退出确认提示。退出操作要求配置退出后识别的画面，当前迷失之地等待挑战结果的完成按钮。结果页 B 完成后需实际看到入口；失败路径返回失败，不进入通关计数或周期奖励完成状态的更新。

从通用结果页恢复时也须核对结果：当前验证的评级为 S（通关）和 X（未通关）；其他或无法识别的评级明确停止，不推测完成。退出途中的周期重置提醒须核对完整提示与 A，确认一次后继续等待入口。

武备奖励选中后的「获得武备」页需要额外一次 A：核对标题、唯一武备名称及绿色 A 提示；连续选择流程还核对其与已选名称一致。每个获得提示只确认一次，后续仍须观察返回场景或挑战结果，不能把按键发送计作完成。

迷失之地后台单选先处理首次教学，定位确定文字左侧的 A 并等待其恢复绿色后识别卡名；NEW 之后复用现有优先级排序，包含战斗组与最后才补位的放弃组，再用黄色边框确认实际焦点。回复事件仍遵循「无详情 获得鸣徽」配置。确认后只观察返回场景、挑战结果或事件后出现的新鸣徽页，不重复按 A。精英结算确认同样只发一次 A，以实际出现下一层或下一选择页作为成功依据。武备的携带记录只在读取到上方实际装备名称后更新。
